この後に、外部 CMS・全文検索エンジン・DB を組み合わせるもう少し本格的な
学習プロジェクトを予定している。そこで使う技術の「縮小版」を先に一通り
触っておきたくて、数時間で終わる小さいサイトから始めることにした。
まずは土台になる Astro とローカル開発の流れに慣れる。

## Astro は何を解決するのか

Web サイトの作り方には、大きく2つある。

- **動的**: 閲覧者がアクセスするたびに、サーバー上でプログラムを動かして
  HTML をその場で組み立てる。ログイン後の画面のように「人によって中身が変わる」
  ものはこれが要る。代わりに、サーバーを常時動かし続ける必要がある。
- **静的**: ページの中身が誰に対しても同じなら、HTML を**事前に1回だけ**作って
  おけば足りる。あとはそのファイルを配るだけ。

学習ログ・ブログ・ドキュメントサイトのように「中身が閲覧者によって変わらない」
ものは、動的の仕組みがまるごと過剰になる。Astro は
**「元ファイル(Markdown やコンポーネント)から、ビルド時に全ページの HTML を
作っておく」** ためのツール。この種類のツールを静的サイトジェネレーター
(SSG, Static Site Generator)と呼ぶ。

出来上がりはただの HTML/CSS/JS なので、配信は「ファイル置き場」で済む。
これが「速い・安い・壊れにくい」の理由になる(別記事で詳しく書いた)。

## なぜ Astro を選んだか

同じ SSG でも方針はいろいろある。Astro を選んだ理由は主に2つ。

1. **Markdown をそのまま記事にできる**。frontmatter(ファイル冒頭の `---` で
   囲んだメタ情報)にタイトルや日付を書けば、あとはビルドが記事ページを作ってくれる。
2. **デフォルトで JavaScript をブラウザに送らない**。ページは基本ただの HTML で、
   動きが必要な部分(このサイトだと検索ボックス)にだけ JS を足す。
   ページ全体を JS で描画する作りに比べて、表示が速く・仕組みも追いやすい。

## `.astro` ファイルの形

コンポーネントやページは `.astro` という拡張子のファイルに書く。
中身は上下2つに分かれている。

```astro
---
// フロントマター: ビルド時に PC 上で走る JavaScript / TypeScript。
// ファイルを読む、データを整形する、といった「下ごしらえ」をここでやる。
const title = "はじめての Astro";
---

<!-- テンプレート: 出力される HTML。{ } の中には上で作った値を差し込める。 -->
<h1>{title}</h1>
```

`---` の中と外で「いつ・どこで動くか」が違う。ここは最初に混乱したので、
別記事「`.astro` の2つの JS 領域」にまとめた。

## Python に慣れていて新鮮だったこと

- **「実行前にビルドする」工程が挟まる**。Python はソースをそのまま
  `python script.py` で動かすが、Astro は `npm run build` で
  元ファイル → ブラウザ用の HTML/CSS/JS へ変換してから動く。
  データ分析でいう「前処理スクリプトを回して成果物を吐く」に近い。
- **ファイルの置き場所に意味がある**。`src/pages/` に置いた
  ファイル名がそのまま URL になる。`src/pages/about.astro` → `/about`。
- **保存すると即反映される**。`npm run dev` で開発用サーバーが立ち、
  ファイルを保存するとブラウザが自動で更新される。試行錯誤が速い。

## 最初にやったこと

```bash
npm create astro@latest    # 雛形を対話的に作る(最小構成 + TypeScript を選択)
npm run dev                 # 開発サーバーを起動、ブラウザで localhost を開く
```

この時点では初期画面が出るだけ。ここから記事スキーマ → 記事 → レイアウト →
一覧・詳細ページ → 検索、と組み立てていく。
