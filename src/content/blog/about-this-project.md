このサイトは、Web フロントエンドをほぼ触ったことがない状態から、
**Astro で静的サイトを作る一連の流れを体験する**ために作った学習プロジェクト。
このブログに載っている記事群が、そのまま学習ログになっている。

## 前提(どのくらいの初心者か)

- Python と SQL でのデータ分析はやってきた。プログラミングの基礎や
  データベースの考え方は分かる
- 一方で **JavaScript / TypeScript / モダンなフロントエンド・デプロイは初学者**。
  `.astro` や `.yml` のスクリプトが何をしているのか、最初はほとんど読めなかった

その「読めなかった」を埋めるために、使った言語ごとの入門記事も別に書いた
(タグ `basics`)。この記事はその見取り図。

## 何を作ったか

「学習ログ」という体裁の、ごく小さい静的サイト。

- Markdown で書いた記事を、スキーマ付きの「表」として管理する
  (Astro の content collection)
- トップに記事一覧、記事ごとの個別ページ、タグ別の一覧ページ
- ヘッダーにクライアントサイド検索(タイトル・本文の部分一致)
- push すると GitHub Actions がビルドし、GitHub Pages へ自動公開

凝ったデザイン・テスト・外部サービス連携は意図的に外した。
「まず動く最小限」を優先している。

## なぜこの構成か

この後にもう少し本格的な学習プロジェクトを予定していて、そこで使う技術の
**縮小版**を先に一通り触っておきたかった。対応はこんなイメージ。

| このプロジェクト | 本番で置き換わる予定 |
|---|---|
| Markdown + content collection | 外部の CMS |
| ブラウザ内の部分一致検索 | 全文検索エンジン |
| GitHub Pages | 別のホスティングサービス |

骨格が同じなら、本番の設定も「見たことのある絵」になる、という狙い。

## どうやって作ったか(Claude Code との進め方)

Claude Code はターミナルで動く AI コーディングエージェント。
ペアプログラミングの相手として使った。うまくいったやり方:

- **先に計画を書く**。`PLAN.md` に手順とゴールを並べ、各ステップに
  「何をするか」「なぜ / 何を学ぶか」を明記してから着手した
- **小さく進める**。ステップごとにコミットし、機能単位でブランチを切って
  Pull Request にし、レビュー(自分で差分を読む)してからマージした
- **分かったことをその場で書き留める**。`KNOWLEDGE.md` に用語や
  つまずきを溜めていった。この入門記事群はそれをベースに書いている
- **調べ物と手を動かす部分を分担**。ビルドエラーの原因調査やドキュメントの
  確認は任せ、設計判断と「なぜそうなるか」の理解は自分でやる

「コードは書けるが、なぜ動くか分からない」状態にならないよう、
新しい概念が出るたびに一言説明を挟んでもらった。
