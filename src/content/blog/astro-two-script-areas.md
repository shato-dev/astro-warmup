1つの `.astro` ファイルに、性質のまったく違う JavaScript が2種類入りうる。
`---` で囲んだ**フロントマター**と、テンプレート中に書く **`<script>`**。
見た目が近いので同じものに見えるが、実行される場所も時間も別。

## 対比

| | フロントマター `---` の中 | クライアント `<script>` の中 |
|---|---|---|
| いつ動く | **ビルド時**に1回だけ | **閲覧者がページを開くたび**、毎回 |
| どこで動く | 自分の PC(Node.js) | 閲覧者のブラウザ |
| できること | ファイル読み込み、`getCollection()`、API 呼び出しなど何でも | ブラウザ内のことだけ(DOM 操作、`fetch()`、クリック処理) |
| 秘密情報 | 置いてよい(出力 HTML には残らない) | **置くと閲覧者に丸見え**。API キーなどは NG |
| 完成品への残り方 | 消える。HTML を組み立てたら役目終了 | バンドルされて `dist/` に同梱・配布される |

フロントマターは「前処理スクリプト」、`<script>` は「ページに同梱して配る
アプリのコード」。まったく用途が違う。

## 具体例

```astro
---
// ビルド時。PC 側。記事データを読んでいる。
import { getCollection } from 'astro:content';
const posts = await getCollection('blog');
console.log(posts.length); // ← このログはビルドを回したターミナルに出る
---

<h1>記事は {posts.length} 本</h1>

<script>
  // ブラウザ側。閲覧者の端末で動く。
  console.log('ページが開かれた'); // ← このログは閲覧者の devtools に出る
  document.querySelector('button')?.addEventListener('click', () => {
    alert('クリックされた');
  });
</script>
```

同じ `console.log` でも、出る先が違う。

## 境界を越えられない

フロントマターの `posts` を、`<script>` の中でそのまま参照することは
**できない**。エラーになる。2つは「別ファイル同士」くらい離れていると
思っておくのが正しい。

理由は実行タイミング。`<script>` が閲覧者のブラウザで動く頃には、
フロントマターはとっくに(ビルド時に)実行し終わって消えている。
`posts` という変数はもうどこにも存在しない。

## どうやってデータを渡すか

ビルド時に用意した値をブラウザ側で使いたいときは、明示的に「橋渡し」する。
主に3つの方法がある。

1. **HTML に埋め込む**。`<script>` タグに `define:vars` を付けると、
   フロントマターの値を `<script>` 内の変数として渡せる。
   ただし値は HTML に文字列として書き出されるので、秘密情報は渡せない。
2. **DOM 属性に書いておく**。`<div data-count={posts.length}>` としておき、
   `<script>` 側で `element.dataset.count` を読む。
3. **別ファイルにして `fetch` する**。ビルド時に JSON ファイルを吐いておき、
   ブラウザ側で必要になったタイミングで取りに行く。

## 検索ボックスはこの構造そのもの

このサイトの検索は 3 番の方法を使っている。

- **ビルド時**(フロントマター側の仕組み): 全記事を
  `[{ title, body, url, ... }]` の JSON ファイル `search.json` に書き出す。
- **閲覧時**(`<script>` 側): 検索ボックスに文字が入ったら
  `search.json` を `fetch` し、`title` と `body` を部分一致で絞り込んで
  結果を表示する。

「重い下ごしらえはビルド時に済ませ、ブラウザには軽い仕事だけさせる」。
Astro でものを作るときの基本の分け方だと思う。
